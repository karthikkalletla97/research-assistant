Claude-Powered RAG Assistant with Production Reliability Patterns

Claude API RAG LangChain / LangGraph NestJS PostgreSQL Production Patterns

A Claude-powered RAG assistant that answers natural-language questions over CRM notes. It combines in-memory hybrid retrieval with a LangChain/LangGraph pipeline and production reliability patterns — circuit breaker, retry, multi-level caching, and observability — built in from the start. (Portfolio project.)

🏗️ ARCHITECTURE (LangGraph PIPELINE)

Classify - Chain-of-thought complexity check routes simple vs. complex queries
Retrieve - In-memory hybrid search: BM25 + Jaccard token overlap + metadata boosts, fused 50/30/20
Select - Importance-weighted chunk selection within a 5K-token budget
Generate - Pass selected chunks to Claude for evidence-based answers
Orchestration - LangChain/LangGraph state machine with conditional routing between steps

⚙️ PRODUCTION PATTERNS (6 CORE SYSTEMS)

Circuit Breaker

CLOSED → OPEN → HALF_OPEN. Prevents cascading failures. Fails fast, recovers automatically after 60s timeout.

Retry Logic

Exponential backoff (100ms → 200ms → 400ms). Handles transient failures gracefully. Max 3 retries.

Multi-Level Caching

Exact-match (hash) and near-duplicate extraction caches plus a response cache, so repeat or near-identical inputs skip redundant Claude calls.

Model Routing

Simple queries → Claude Haiku (cheap, fast). Complex → Opus (quality). Routed by query complexity to control cost.

Observability

Metrics endpoints tracking latency, cost-per-call, cache-hit rate, candidates retrieved, and context utilization.

Context Management

Chunking (~500 tokens with ~50-token overlap) and importance-weighted selection (0.7 × relevance + 0.3 × recency) within a 5K-token budget.

📚 DESIGN DECISIONS

Why hybrid lexical retrieval? An early TF-IDF approach scored relevant notes near zero on matching queries. Rebuilt as BM25 + Jaccard + metadata fusion, which fixed retrieval on the eval set.

Why Haiku + Opus? Route by query complexity — cheap/fast model for simple lookups, stronger model for complex reasoning — instead of paying for the big model on every call.

Why Circuit Breaker? The Claude API can fail. Fail fast, recover automatically, don't cascade failures.

Next step: Dense embeddings + pgvector (and cross-encoder reranking) to add true semantic retrieval at scale.
